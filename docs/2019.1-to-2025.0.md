This document describes the original one-time curation audit. The current website uses frozen snapshots and the taxonomy-only engine described in [release architecture](release-architecture.md). Comparison PDF generation has been retired.

# 2019.1 to 2025.0 migration

This project converts the corrected 2019.1 checklist into the taxonomy and category model used for the first EBD/AviList release. It is a one-time migration, not part of the recurring release pipeline.

## Inputs

- `data/legacy/2019.1/checklist.csv`: corrected historical checklist.
- `data/legacy/2019.1/2019 Checklist of the Birds of Kenya 5th Edition (2019).pdf`: source edition.
- `data/curation/taxonomy_2019.1_to_2025.0.csv`: reviewed many-to-many taxonomy crosswalk.
- `data/curation/earc_decisions.csv`: curated Kenya species-level EARC national-list decisions, keyed only by the current AviList `avibase_id`.
- `dist/v2025.0/checklist.csv`: checklist produced by the current release build.

The crosswalk contains `old_avibase_id` and semicolon-separated `new_avibase_ids`. A blank target means that the historical concept has no current equivalent. The migration derives replacements, splits, lumps, and many-to-many groups. Complex taxonomy changes remain in the category audit and are never transferred silently.

The EARC table is initialized from `earc_decisions.csv` in the Scopus research workflow. It retains only Kenya species-level decisions that resolve a species added to or discontinued from the checklist since 2019. A `Pending EARC` change is therefore a 0:1 or 1:0 group with no mapped EARC decision. For v2025.0 this gives 15 pending change groups, including 13 species present on the current checklist. They remain included for review in a later version. Accepted and rejected decisions are record-review annotations; neither the checklist nor comparison removes a species because a record was rejected.

## Generate and review the migration

Run from the repository root:

```sh
python3 scripts/compare_2019.1_to_2025.0.py
```

Review these generated files under `dist/v2025.0/comparison/`:

- `unresolved-old-taxa.csv`
- `current-only-taxa.csv`
- `category-migration-audit.csv`
- `categories-converted.csv`
- `taxonomy-changes.csv`
- `taxonomy-changes.json`
- `taxonomy-changes.html`

`taxonomy-changes.json` supplies the public changes page. The standalone HTML is a release-review artifact. Both keep connected historical and current concepts together and follow current AviList sequence.

After reviewing the crosswalk and category audit, render the printable comparison:

```sh
# Retired: comparison PDF rendering
```

The PDF is written to `dist/v2025.0/comparison/` and staged in `release-assets/v2025.0/comparison/` for the website.

## Retention

The corrected checklist and source edition remain in `data/legacy/2019.1/` because they are maintained migration inputs. The public comparison files are versioned under `release-assets/`; `dist/` does not need to remain on the branch.
